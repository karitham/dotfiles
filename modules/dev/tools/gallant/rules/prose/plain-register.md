# Plain technical register

Documentation reads as a specification, not as persuasion. It states what is
true, why, and at what cost.

- **Violates** — descriptive prose that addresses the reader or the authors as
  "you", "your", "we", "our" or "us". Imperative instructions such as "Run
  `make`" are fine; they have no pronoun.
- **Violates** — hedging or filler: "simply", "just", "basically", "really",
  "very", "it is worth noting that", "in order to".
- **Violates** — persuasion or marketing: "powerful", "seamless", "blazing fast",
  "best-in-class", "effortless", "robust".
- **Violates** — bold or italics used for emphasis in running sentences, rather
  than for a term being defined or a label at the start of a list item.
- **Violates** — software described as having intent: a component that "wants",
  "knows", "decides" or "tries".
- **Does not violate** — quoted text, code blocks, command output and examples
  of what not to write.
- **Does not violate** — bold labels at the start of list items, like the ones
  in this rule.

Report a violation only when you can point to a sentence that does one of the
above. Judge the prose, not the subject it describes.
